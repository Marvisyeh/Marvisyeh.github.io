FindGoods 找好家飾：家飾電商聚合與推薦系統

在疫情與遠端工作興起的背景下，設計一個整合多家電商的家飾聚合平台，結合個人化推薦與以圖搜圖，幫助使用者更快找到理想家飾。

Feb 16, 2022
1 minute read

專案背景

疫情與遠端工作的普及，讓很多人開始花更多心力在「家裡的佈置與舒適」。
但實際在逛家飾時，常見的痛點是：

  • 不同電商平台的商品分散，很難一次比較
  • 想要找「某種風格」的家飾，卻不知道關鍵字要怎麼下
  • 看到了喜歡的圖片（例如 IG、Pinterest），但很難找到「類似風格」的實際商品

FindGoods 找好家飾 是我和夥伴設計的一個 side project，目標是：

整合多個家飾電商平台的商品，並提供「個人化推薦」與「以圖搜圖」功能，讓使用者可以用更自然的方式找到自己喜歡的家飾。

查看原始程式碼（GitHub）

系統概覽與資料流

整體系統可以拆成幾個主要模組：

  1. 資料蒐集與整合

    • 透過爬蟲或 API，從多個家飾電商平台收集商品資訊（圖片、標題、價格、類別、材質…）
    • 將原始資料先寫入 MongoDB / 檔案系統，做為原始素材

  2. 資料處理與特徵建模

    • 將結構化資料（價格、類別、風格標籤等）整理進 MySQL，方便做篩選與報表
    • 對商品圖片進行特徵擷取（例如使用 CNN / Pretrained Model），把每張圖轉成向量嵌入（Embedding）
    • 儲存這些向量，作為「以圖搜圖」與「相似商品推薦」的基礎

  3. 應用層：瀏覽、推薦與以圖搜圖

    • 依照使用者行為與商品特徵，產生個人化推薦清單
    • 使用者上傳圖片後，從向量空間找到「視覺上相似」的商品

  4. 前端介面與使用者體驗

    • 以 Flask 為後端框架，提供 API 與頁面渲染

系統架構設計

在架構上，我們把整個系統拆成幾層：

  • Presentation Layer（前端 / Web）

    • 使用者可以透過 Web 介面：
      • 瀏覽推薦商品
      • 上傳一張圖片進行「以圖搜圖」

  • Data & ML Services（推薦 / 圖片檢索）

    • 推薦系統服務：根據使用者歷史與商品特性產生候選清單
    • 圖片特徵檢索服務：接收一張圖片 → 轉成向量 → 在向量空間中找出最近鄰商品

  • Data Storage Layer

    • MongoDB：儲存原始商品資料與較彈性的欄位
    • MySQL：儲存結構化後的商品資訊與行為資料（例如點擊、收藏）
    • 檔案系統 / 物件儲存：儲存商品圖片與預先計算好的特徵向量

個人化推薦：從使用者行為到商品清單

在個人化推薦部分，我們採用了「內容為主的推薦（Content-based Filtering）」為主，結合部分行為訊號：

使用的訊號包含：

  • 使用者操作行為：瀏覽、點擊
  • 商品屬性：風格（北歐、工業、日系…）、材質（木頭、金屬）、空間（客廳、臥室…）

基本作法：

  1. 將商品屬性轉成特徵向量
  2. 將使用者喜歡 / 常看的商品向量加總或做加權平均，形成「使用者偏好向量」
  3. 計算使用者向量與所有商品向量的相似度（例如 Cosine Similarity）
  4. 排序後，過濾掉使用者已看過或不在預算範圍內的商品，做為推薦結果

這個專案雖然沒有做到大型商業系統那種 Matrix Factorization 或 Deep Learning 級別的推薦，但專注在「把內容特徵整理好、推薦邏輯清楚」，已經能做出有感的結果。

我的角色與負責內容

在這個 Side Project 中，我主要負責：

  • 推薦邏輯的設計與實作（Content-based Recommender）

專案成果與心得

雖然 FindGoods 是一個 side project，但它讓我在「資料產品」這件事上有更完整的實戰經驗：

  • 從需求（使用者怎麼逛家飾）出發設計資料流，而不是先選技術
  • 把推薦系統與資料工程串成一個「完整產品」，而不是分散的 demo
  • 練習如何在有限資源下，選擇可行但有感的解法，而不是一開始就追求最複雜的模型
