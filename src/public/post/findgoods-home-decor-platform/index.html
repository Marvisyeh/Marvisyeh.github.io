Side Project｜FindGoods 找好家飾：家飾電商聚合與推薦系統

在疫情與遠端工作興起的背景下，設計一個整合多家電商的家飾聚合平台，結合個人化推薦與以圖搜圖，幫助使用者更快找到理想家飾。

Mar 01, 2021
1 minute read

專案背景：為什麼會有 FindGoods？

疫情與遠端工作的普及，讓很多人開始花更多心力在「家裡看起來舒服好不好」。
但實際在逛家飾時，常見的痛點是：

  • 不同電商平台的商品分散，很難一次比較
  • 想要找「某種風格」的家飾，卻不知道關鍵字要怎麼下
  • 看到了喜歡的圖片（例如 IG、Pinterest），但很難找到「類似風格」的實際商品

FindGoods 找好家飾 是我和夥伴設計的一個 side project，目標是：

整合多個家飾電商平台的商品，並提供「個人化推薦」與「以圖搜圖」功能，讓使用者可以用更自然的方式找到自己喜歡的家飾。

系統概覽與資料流

整體系統可以拆成幾個主要模組：

  1. 資料蒐集與整合

    • 透過爬蟲或 API，從多個家飾電商平台收集商品資訊（圖片、標題、價格、類別、材質…）
    • 將原始資料先寫入 MongoDB / 檔案系統，做為原始素材

  2. 資料處理與特徵建模

    • 將結構化資料（價格、類別、風格標籤等）整理進 MySQL，方便做篩選與報表
    • 對商品圖片進行特徵擷取（例如使用 CNN / Pretrained Model），把每張圖轉成向量嵌入（Embedding）
    • 儲存這些向量，作為「以圖搜圖」與「相似商品推薦」的基礎

  3. 應用層：搜尋、推薦與以圖搜圖

    • 提供關鍵字搜尋、條件篩選（價格區間、風格、材質等）
    • 依照使用者行為與商品特徵，產生個人化推薦清單
    • 使用者上傳圖片後，從向量空間找到「視覺上相似」的商品

  4. 前端介面與使用者體驗

    • 以 Flask 為後端框架，提供 API 與頁面渲染
    • 設計簡單但專注在「找得到、比得清楚」的 UI 流程

系統架構設計

在架構上，我們把整個系統拆成幾層：

  • Presentation Layer（前端 / Web）

    • 使用者可以透過 Web 介面：
      • 搜尋關鍵字
      • 瀏覽推薦商品
      • 上傳一張圖片進行「以圖搜圖」

  • Application Layer（Flask 後端）

    • 負責處理 HTTP Request、參數驗證，與後端服務溝通
    • 提供 RESTful API 給前端（或未來可能的 App 客戶端）

  • Data & ML Services（推薦 / 圖片檢索）

    • 推薦系統服務：根據使用者歷史與商品特性產生候選清單
    • 圖片特徵檢索服務：接收一張圖片 → 轉成向量 → 在向量空間中找出最近鄰商品

  • Data Storage Layer

    • MongoDB：儲存原始商品資料與較彈性的欄位
    • MySQL：儲存結構化後的商品資訊與行為資料（例如點擊、收藏）
    • 檔案系統 / 物件儲存：儲存商品圖片與預先計算好的特徵向量

個人化推薦：從使用者行為到商品清單

在個人化推薦部分，我們採用了「內容為主的推薦（Content-based Filtering）」為主，結合部分行為訊號：

使用的訊號包含：

  • 使用者操作行為：瀏覽、點擊、加入收藏、加到購物清單（如果有的話）
  • 商品屬性：風格（北歐、工業、日系…）、材質（木頭、金屬）、空間（客廳、臥室…）
  • 價格區間與品牌偏好

基本作法：

  1. 將商品屬性轉成特徵向量（例如 One-hot / Multi-hot Encoding）
  2. 將使用者喜歡 / 常看的商品向量加總或做加權平均，形成「使用者偏好向量」
  3. 計算使用者向量與所有商品向量的相似度（例如 Cosine Similarity）
  4. 排序後，過濾掉使用者已看過或不在預算範圍內的商品，做為推薦結果

這個專案雖然沒有做到大型商業系統那種 Matrix Factorization 或 Deep Learning 級別的推薦，但專注在「把內容特徵整理好、推薦邏輯清楚」，已經能做出有感的結果。

以圖搜圖：從圖片到相似家飾

「以圖搜圖」是這個專案裡最有趣的部分之一。

需求場景：

  • 使用者在 Instagram / Pinterest 看到一張喜歡的客廳照片
  • 他可以截圖上傳到 FindGoods
  • 系統會找出「在風格與顏色上類似」的沙發、抱枕、燈具等商品

大致流程：

  1. 特徵擷取（Feature Extraction）

    • 使用預訓練好的 CNN 模型（例如 ResNet / VGG 等）
    • 把最後一層或倒數幾層的特徵向量取出，作為圖片的 Representation

  2. 向量儲存與檢索

    • 將所有商品圖片的向量預先計算好並儲存
    • 使用簡單的最近鄰搜尋（例如 Cosine Similarity / Euclidean Distance），或引入向量搜尋工具

  3. 查詢流程

    • 使用者上傳一張圖片
    • 透過同一個 CNN 模型抽特徵 → 得到查詢向量
    • 計算與所有商品向量的相似度，取 Top K 作為推薦結果

這個功能的重點不在於「模型多複雜」，而是在於：
如何把整個流程打通，讓使用者真的可以用一張圖片完成一次有效的搜尋。

我的角色與負責內容

在這個 Side Project 中，我主要負責：

  • 系統資料流與架構設計（Data Flow / System Diagram）
  • 商品資料的整理與建模（MongoDB + MySQL 結構設計）
  • 推薦邏輯的設計與實作（Content-based Recommender）
  • 以圖搜圖部分的資料流規劃與模型串接
  • 與前端合作定義 API 介面與回傳格式

專案成果與學到的事

雖然 FindGoods 是一個 side project，但它讓我在「資料產品」這件事上有更完整的實戰經驗：

  • ✅ 從需求（使用者怎麼逛家飾）出發設計資料流，而不是先選技術
  • ✅ 把推薦系統、搜尋與資料工程串成一個「完整產品」，而不是分散的 demo
  • ✅ 練習如何在有限資源下，選擇可行但有感的解法，而不是一開始就追求最複雜的模型

幾個重要的學習：

  1. 資料產品 = 工程 + 資料 + 使用者體驗
    單純把模型做好還不夠，必須確保它能被真正的使用流程消化。

  2. 從簡單的推薦方法開始是完全 OK 的
    先讓系統可用、可解釋，再逐步迭代到更進階的演算法。

  3. 視覺搜尋讓「逛」這件事變得更自然
    對家飾這種強調風格與美感的品類來說，「圖像特徵」有時比文字還更接近使用者的心裡想像。
